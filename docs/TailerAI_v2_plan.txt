                        LaTeX-Powered Resume Generation Platform
================================================================================

EXECUTIVE SUMMARY
=================
TailerAI v2.0 represents a complete paradigm shift from DOCX-based resume generation 
to LaTeX-powered PDF output, delivering pixel-perfect formatting that matches exact 
college-accepted resume formats. This version prioritizes professional presentation, 
one-page constraint compliance, and free internet hosting accessibility.

PROJECT SCOPE & OBJECTIVES
==========================
Primary Goal: Create a LaTeX-based resume generation system that produces 
              college-quality, one-page resumes with exact formatting precision.

Secondary Goals:
- Deploy on free hosting platform for global accessibility
- Maintain AI-powered content optimization capabilities  
- Ensure consistent output across all devices and platforms
- Provide both PDF (primary) and editable format (secondary) outputs

TECHNICAL ARCHITECTURE OVERVIEW
===============================

Core Technology Stack:
- Backend: Python FastAPI (lightweight, API-focused)
- LaTeX Engine: TeX Live with custom templates
- AI Processing: Google Gemini API (cost-effective, powerful)
- Frontend: Vanilla JavaScript (no heavy frameworks)
- Hosting: Free tier cloud platform (Render.com recommended)
- Database: SQLite (serverless, embedded)

Key Differentiators:
- LaTeX-first approach for professional output quality
- MSPM-validated template matching exact format requirements
- One-page guarantee with intelligent content optimization
- Zero-cost hosting with professional-grade performance

Docker Configuration (Dual Environment):
```dockerfile
# Multi-stage build for efficiency
FROM python:3.11-slim as base

# Install TeX Live and dependencies
RUN apt-get update && apt-get install -y \
    texlive-latex-base \
    texlive-latex-extra \
    texlive-fonts-recommended \
    texlive-fonts-extra \
    curl \
    && rm -rf /var/lib/apt/lists/*

# Development stage
FROM base as development
WORKDIR /app
COPY requirements.txt .
RUN pip install -r requirements.txt
COPY . .
EXPOSE 8002
CMD ["uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8002", "--reload"]

# Production stage (Google Cloud Run)
FROM base as production
WORKDIR /app
COPY requirements.txt .
RUN pip install -r requirements.txt --no-cache-dir
COPY . .
# Cloud Run uses PORT environment variable
EXPOSE $PORT
CMD exec uvicorn app.main:app --host 0.0.0.0 --port $PORT
```

Environment Configuration:
```python
# app/config/settings.py
import os
from pydantic_settings import BaseSettings

class Settings(BaseSettings):
    # Environment detection
    environment: str = os.getenv("ENVIRONMENT", "development")
    
    # Server configuration
    host: str = "0.0.0.0"
    port: int = int(os.getenv("PORT", 8002))
    
    # Database URLs
    database_url: str = (
        os.getenv("DATABASE_URL", "sqlite:///./data/database/tailer_v2.db")
        if os.getenv("ENVIRONMENT") != "production"
        else os.getenv("CLOUD_SQL_CONNECTION_STRING")
    )
    
    # Google Cloud configuration
    google_cloud_project: str = os.getenv("GOOGLE_CLOUD_PROJECT", "")
    google_cloud_storage_bucket: str = os.getenv("GCS_BUCKET", "")
    
    # AI service configuration
    gemini_api_key: str = os.getenv("GEMINI_API_KEY", "")
    
    class Config:
        env_file = ".env"
```
